# Architecture

`app.py` owns camera capture, optional OpenCV HOG baseline, detector/tracker selection, calibration mapping, and the local stdlib HTTP server. `detection.py` implements the existing detector contract plus an optional local Ultralytics YOLO adapter. `tracking.py` adapts detector rows to BoxMOT BoT-SORT and estimates latency-aware image-pixel lead positions. The fallback remains greedy IoU. `monitor.py` contains both the existing industrial rules and the opt-in public-area event rules; public-area polygons are normalized image coordinates and events update in the camera loop. The browser dashboard consumes JSON endpoints and MJPEG. `assistant.py` is a separate, disabled-by-default Gemini API client for explicitly requested Gemma scene summaries; it receives minimized tracked-scene metadata, never calls from the frame loop, and only attaches a downsized image when the server configuration and individual user request both opt in.

The seams are intentionally small: replace the detector behind the frame loop; replace `Tracker.update` behind the track update boundary; replace `localize` with a LocalizationProvider; monitoring rules consume tracked-object observations. The optional BoxMOT adapter accepts `[x1,y1,x2,y2,confidence,class_id]` rows and preserves the existing tracked-object JSON fields. Public-area rules use temporary person tracks and configured image polygons. Warnings include a local operator-review draft, but no message is sent or emergency service contacted. Lead-ahead estimates are advisory image coordinates (or calibrated camera-plane coordinates), based on measured in-process detection/tracking latency; they do not estimate camera-to-screen or sensor-network delay.

The assistant is not part of the perception or safety path. Its scene summary contains aggregated classes/states/event-rule counts and selected system status, but omits track IDs, coordinates, event messages and image data by default. API use is a user-triggered outbound network request and is explicitly disclosed in the dashboard.

Localization requires four image points and matching room-plane meter points in `localization.yaml` (or `config/localization.yaml` in a packaged layout). Coordinates describe the calibrated plane, not GPS. A homography only applies when the camera and target ground plane remain fixed.
